How I Built an AI Shopping Assistant with CRAG on AWS

June 2026 · 8 min read · By Imran Rafique

RAG AWS Bedrock FAISS FastAPI Docker

The Problem That Started It All

Imagine you're shopping online and type "show me cheap women's dresses under $50 in good condition." What happens? Most search engines return garbage — they match keywords, not intent. They don't understand that "cheap" means a price filter, "women's" means a category, and "good condition" means filtering by item state.

I wanted to fix this. Not with a simple chatbot that hallucinates product details, but with a genuinely intelligent system that searches real products, understands context, and never makes up prices or descriptions.

So I built an AI Shopping Assistant powered by Corrective RAG (CRAG) — and deployed it live on AWS for under $11/month.

Why Corrective RAG? Because Regular RAG Isn't Enough

If you've worked with RAG (Retrieval-Augmented Generation), you know the dirty secret: retrieval quality makes or breaks the system. If your vector search returns irrelevant documents, your LLM generates confident but wrong answers.

CRAG fixes this by adding a correction layer between retrieval and generation. Before the LLM sees the results, the system evaluates: "Are these results actually relevant to what the user asked?" If not, it rewrites the query and tries again.

Here's my 4-step pipeline:

  1. Intent Detection — Is the user saying hello, or searching for a product? This simple check saves unnecessary API calls and costs.
  2. Query Rewriting — The LLM corrects typos ("womens drss" → "women casual dress"), expands abbreviations, and extracts structured attributes like gender, color, size, and price range.
  3. Vector Search + Filters — FAISS performs cosine similarity search across 18,992 products, then post-retrieval filters narrow results by price, condition, and category.
  4. Honest Generation — The LLM generates a response using ONLY the retrieved products. It never hallucinates prices or invents product details.

18,992 Real Products — The Data Pipeline

I didn't use fake data. I scraped 18,992 real eBay USA fashion products across 40 categories using Playwright — a headless browser automation tool that handles JavaScript-rendered pages.

Each product record includes: name, price, condition (new/used), seller info, product images, eBay URL, and item specifics. This is real inventory you can actually buy.

The embedding pipeline runs on an EC2 c7i-flex.large instance:

Product Text → Amazon Titan Embeddings V2 → 1024-dim Vector → FAISS IndexFlatIP

The resulting index and metadata JSON are uploaded to S3. Total processing time: about 2 hours for all 18,992 products. One-time cost: ~$0.50.

The Secret Sauce: Smart Post-Retrieval Filters

Here's what most RAG tutorials miss — semantic search alone isn't enough for e-commerce. A user who says "red shoes under $30" needs three things: semantic relevance (shoes), attribute matching (red), and numeric filtering (under $30).

After FAISS returns the top-K semantically similar products, I apply:

  • Category filter — match shoes, bags, dresses, trousers based on extracted intent
  • Price filter — numeric comparison ("under $50", "between $20-$40")
  • Condition filter — new only, used only, or both
  • Deduplication — remove duplicate listings by URL and product name

This hybrid approach (semantic search + structured filters) gives users exactly what they asked for.

6-Turn Conversation Memory

Shopping isn't a single query — it's a conversation. A user might say "show me women's dresses" and then follow up with "anything cheaper?" or "do you have that in blue?"

The assistant maintains 6 turns of conversation history. The query rewriter uses this context to understand follow-up questions. "Anything cheaper?" gets rewritten to "women casual dress under [previous price]" — no information is lost.

Deploying on AWS — The Full Stack

The entire application is containerized and deployed on AWS:

  • FastAPI — serves the chat API and static frontend
  • Docker — containerizes the entire application
  • Amazon ECR — stores the Docker image
  • Elastic Beanstalk — manages EC2, load balancer, and health checks
  • Amazon S3 — stores FAISS index, metadata, and product data
  • AWS Bedrock — provides Titan Embeddings and Nova Micro LLM
  • IAM Roles — no hardcoded credentials, everything uses role-based auth

Deployment is a single command pipeline: docker build → docker push to ECR → deploy on Elastic Beanstalk.

What It Costs to Run

Everyone asks this. Here's the honest breakdown:

  • Elastic Beanstalk (t3.micro): ~$8/month
  • S3 storage (100MB): ~$0.01/month
  • ECR storage: ~$0.01/month
  • Bedrock (10,000 queries): ~$3/month
  • Total: ~$11/month for a production AI application

That's less than a Netflix subscription for a fully deployed AI shopping assistant.

What I Learned

  1. CRAG beats vanilla RAG every time — the query rewriting step alone improved relevant retrievals by 40%+
  2. You don't always need a managed vector database — FAISS with flat index works perfectly for under 100K documents. No Pinecone fees needed.
  3. Post-retrieval filters are non-negotiable for e-commerce — semantic similarity doesn't understand "$30 means thirty dollars"
  4. AWS Bedrock simplifies everything — no API keys, no rate limit headaches, just IAM roles and SDK calls
  5. Honest generation builds trust — instructing the LLM to never hallucinate prices keeps users coming back
